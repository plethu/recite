# Recite production specification

The specification defines product and compatibility requirements. It is split by
subsystem so maintainers can read the affected contract without loading the whole
project. Read the chapter and subsection needed for the change. Code and tests
establish implemented behaviour; GitHub owns current task and milestone state.
Historical experiment reports are evidence, not additional specification.
